# FateFlix configuration

FateFlix is a modular downstream of `github:kiriwalawren/nixflix`. Start with
`modules/settings.nix`; its switches and paths are typed in `modules/options.nix`.
Credentials remain runtime file references. Provisioning still uses the existing
SecretSpec profiles and `/var/lib/nixflix-secrets` locations.


Every discovered Nix file under `modules` is a flake-parts module. import-tree
excludes paths containing an underscore, so raw NixOS modules, patches and plugin
assets live under `modules/_support`. The existing `hosts/nixflix`, `scripts`,
`tests`, `lib`, and `pkgs` paths remain stable for operators and callers.

`modules/aspects` registers Den aspects. `modules/hosts` composes production and
staging from them. Both retain hostname `nixflix`; the output names remain
`nixflix`, `nixflix-production`, and `nixflix-staging`. `nixflix` aliases production.
The host uses the existing stable `nixpkgs-host` pin; checks, developer tools and
flake packages use the existing unstable `nixpkgs` pin.

## Generated flake

Input declarations and follows are maintained in `modules/flake/inputs.nix`.
Output definitions, checks and developer tools live beside it. After changing
input declarations, run:

```sh
nix run .#write-flake
nix flake lock
nix build .#checks.x86_64-linux.check-flake-file
```

The static declarations in `flake.nix` are generated by flake-file. Nix requires
them there to resolve dependencies before evaluating modules. Its output wiring
is just flake-parts plus import-tree. Commit new modules before using a Git flake,
or use `path:.` during work on untracked files.

## Download policy

`downloads.torrents.enable = false` overrides torrent clients, Downloadarr torrent
connections, FlareSolverr, Autobrr and cross-seed. Their upstream dashboard and
proxy registrations follow their enable flags. Declared Prowlarr indexers are
restricted to Newznab schemas or explicit `protocol = "usenet"` declarations;
indexer proxies are cleared. Enabling torrents permits individually selected
clients through their existing NixFlix or NixOS options; it enables none itself.

A production-only `fateflix-download-policy` unit also disables disallowed
protocols in restored Arr/Prowlarr state, including download clients, indexers,
search flags and delay profiles. It uses runtime API keys and preserves records.
It runs after the applications and every five minutes. Allowing a protocol never
re-enables old clients or indexers. Staging never runs this reconciliation.

## Upstream adapter

The locked NixFlix input is source-only. `modules/upstream/nixflix.nix` is the only
adapter. Three named patches preserve existing four-instance integrations,
credential startup checks, and notification reconciliation. Downstream NixOS
modules and independently updated plugin/Caddy assets live in
`modules/_support/compat`; package overrides remain in `pkgs` and are exposed by
`modules/overlays/media.nix`. Unmodified upstream modules are no longer vendored.

The adapter builds a small patched source tree with `applyPatches`. Importing its
NixOS modules uses import-from-derivation, so the evaluator needs a builder for
that source derivation (currently x86_64-linux), even for aarch64 checks. This does
not build or activate a system during evaluation. Patch failures stop evaluation
before a new host can be deployed.

Update upstream with `nix flake update nixflix`, review the lock diff, and run the
checks and production build. The existing upstream workflow now creates a
lock-update PR instead of merging another Git tree. Renovate also includes the
input in reviewed system dependency updates. Input declaration edits must happen
in the modules and then be regenerated.

## Verification and rollout

```sh
nix develop --command python3 -m unittest discover -s tests/migration -p 'test_*.py'
nix build .#checks.x86_64-linux.torrent-policy-eval
nix build .#checks.x86_64-linux.production-eval .#checks.x86_64-linux.gitops-eval
nix build .#nixosConfigurations.nixflix-production.config.system.build.toplevel
nix eval --json .#nixosConfigurations.nixflix-production.config.warnings
nix eval --json .#nixosConfigurations.nixflix-staging.config.warnings
```

`modules/_support/host-contract.nix` projects identities, database paths, service
dependencies, timers, networking, storage, GPU packages, containers, versions and
recovery configuration for before/after comparisons. The initial comparison used
the preserved working tree, including its uncommitted production changes. The
reviewed changes through `origin/main` commit `dc59848` are also incorporated:
the corrected Caddy plugin hash, refreshed Jellyfin catalog, and update-workflow
notes. These do not change enabled production package versions. The
new policy unit/timer and the Whisparr network-online dependency are intentional
additions; systemd dependency list ordering has no behavioral effect.
